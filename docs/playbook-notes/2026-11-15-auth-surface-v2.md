## 2026-11-15 - Auth Surface v2: one anatomy, one notice box, one copy matrix

- Type: Auth, install and error UI (source); shared design with FawxzzyWeb and Mazer (Zac approved 2026-11-15)
- WHAT changed: Sign in, remembered sign in, create account, reset request (signed in and signed out), new password, expired link, account hand-off and every install context now use one shell (`src/components/auth/AuthShell.tsx` + the `.fx-*` block in `globals.css`): the real app icon, kicker, title, optional lead, a scrolling body with ONE reserved notice slot (`AuthNoticeSlot`, `role="alert"`, height held when empty), links, legal row and one dock button. The page is a `100dvh` flex column with safe areas in padding; nothing is `position: fixed`, and phones 640 px tall or shorter (320x568) get compact metrics. Every message comes from `src/components/auth/authMessages.ts` (the approved copy matrix, Fitness subset). `authMessages.test.ts` fails when a screen file shows text that is neither a matrix message nor a fixed label, and maps every allow-listed route code to a matrix id. Reset requests never take a typed email: signed in shows the account email locked; signed out asks for the username only. Reset-link problems land on the request screen with the reason (no dead end). Install is one `InstallScreen` per real situation; the iPhone in-app browser (open in Safari, copy link) is distinct from Safari (share steps, no button). The account hand-off shows a fallback link after 6 s. The global `ActionFeedbackToasts` bridge no longer toasts on /login and /signup (the inline box owns those messages) and leaves /reset-password alone.
- WHY it changed: Each screen had its own layout, offsets and wording; messages appeared as toasts, under titles or as button text; the reset-link error was a dead end; the in-app iPhone browser got Safari steps it cannot follow; a repeated identical server error left the button stuck busy.
- Rule: A screen picks a message id; it never writes message text. One notice region per screen, height reserved so nothing shifts. Layout is a flex column with safe areas in padding, never fixed px offsets. A repeated identical server error must still re-enable the button and show the box (route errors are cleared from the URL and re-synced; the reset page remounts its form per server render).
- Failure Mode: A toast bridge plus an inline box shows the same error twice; a page that branches on `?error` breaks if the bridge strips it; source-regex tests on `position: fixed` match comments; border transitions make headless style reads flaky unless transitions are disabled in the proof; `justify-content: center` on a scrolling column pushes overflow above the scroll origin, so the first field cannot be reached in landscape (centre with auto margins instead).
- Decision: The not-found page, app-error screen and global-error keep the FF-DESIGN-004 versions from #262 (card layout, `errorCopy.ts`), which merged while this change was in progress; moving them into the v2 status shell needs one copy source chosen first (`errorCopy.ts` "Something went wrong" vs the matrix "Could not load", which `errorScreens.contract.test.tsx` forbids). `signup_failed` uses a sign-up-specific generic line (`signup.failed`, "Could not create your account. Try again in a minute." with a "Sign in" action) until the owner decides on an "email already has an account" message; the provider's `weak_password` code gets `signup.pwweak`. A username reset that cannot be looked up (no server credential, `email_required`) shows `reset.unavailable` and keeps the username field. `signup.failed` and `reset.unavailable` are copy-matrix additions. A failed sign-up puts back the remembered login from before the attempt (`signupRememberedLogin.ts`).
- Evidence: `npm run test:auth-ui-contracts`, `src/components/auth/authMessages.test.ts`, `src/lib/install/config.test.ts`, `npm run test:auth-autofill`, `npm run test:all`, `scripts/qa/auth-surface-parity-proof.mjs` (v2 geometry incl. 320x568).
- Status: Source only; headless browser checks only; not checked on a real phone; no Supabase, Turnstile or service-worker change.
