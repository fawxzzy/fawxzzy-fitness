## 2026-11-19 - Next 16 move (follow-up to FF-PLATFORM-001)

- Type: framework upgrade (no product behaviour change intended)
- WHAT changed: next / eslint-config-next 15.5.29 -> 16.4.6 (pinned), eslint 8 -> 9.39 with a flat `eslint.config.mjs` run through `scripts/eslint-cli.mjs` (`next lint` is gone in 16). Every helper that reads the request is now async and every caller awaits it (`supabaseServer`, `getRequestAccessToken`, `readCurrentRequestServerSessionTokens`, the `/dev` page guards, the history preview gate, the local-dev auto-entry checks, `getOrigin` / `getAppOrigin`); no `UnsafeUnwrapped*` cast is left. `src/middleware.ts` -> `src/proxy.ts` via the official codemod (function `proxy`, Node runtime). One-argument `revalidateTag` -> `updateTag` in `src/app/actions/exercises.ts`. Test router stubs gain `bfcacheId` (new on `AppRouterInstance`). The production build uses Turbopack (default). React stays 19.2.9. No route, persisted data, env or flag change.
- WHY it changed: Next 15 security releases end 2027-01-31 (nextjs.org/support-policy); Next 16 removes the synchronous request APIs the helpers relied on.
- Rule: A request helper that gates access (`assertDevPageAvailable`, `isHistoryPreviewActiveForRequest`, `isTrustedLocalDevRequest`) must be awaited at every call site; `src/lib/async-request-helpers.contract.test.ts` fails the build on any un-awaited call, and a new async request helper is added to its list.
- Rule: `src/lib/dev-page-guard-runtime.test.ts` imports every guarded `/dev` page and the `/dev` layout with a stubbed `next/headers` and requires a `notFound()` (404) for a production request with no Host, before props are read.
- Failure Mode: Converting a boolean or void guard to async without awaiting it fails open: `if (isHistoryPreviewActiveForRequest())` tests a Promise (always truthy) and `assertDevPageAvailable();` rejects after the page has rendered. Typecheck only catches the Supabase-client cases (a Promise has no `.from`); the guard cases need the contract test. Both tests were mutation-checked with `void assertDevPageAvailable()`.
- Failure Mode: eslint-config-next 16 nests its plugins, so marker files that pointed at hoisted `node_modules/eslint-plugin-*` made `ensure-repo-deps` report missing modules; the marker is now `eslint-config-next/dist/core-web-vitals.js`.
- Decision: eslint 9, not 10 (eslint-plugin-react / import / jsx-a11y peer only up to 9). The React Compiler rules new in eslint-plugin-react-hooks 7 are off (153 existing sites); `rules-of-hooks` and `exhaustive-deps` stay on. Adopting them is a follow-up.
- Evidence: lint, typecheck, test:dom, test:all, build, npm run verify and the headless side-by-side compare against main are in the PR body.
- Status: Source only; not deployed. Signed-in flows cannot run locally (no Supabase env locally) and need an unaliased build check before alias.
