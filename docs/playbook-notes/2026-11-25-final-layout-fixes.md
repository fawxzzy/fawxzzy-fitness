## 2026-11-25 - Final layout fixes from the integrated QA (menu clamp, add-exercise dock, tap target, goal wording)

- Type: UI polish (no data, route, env, flag or server-action change)
- WHAT changed: (1) `Menu` placement is now the pure `resolveMenuPlacement` (below the trigger, flipped above when it does not fit, clamped inside the viewport with an 8px margin, re-measured after the first paint); the routine row menu passes a compact `minWidth={80}` so the Delete panel no longer covers the day chips (WED) at 390 or 320. (2) The add-exercise dock (`ExercisePicker`) opts into the existing wrapping field grid (`wrapMeasurementFields` -> `wrapHorizontalFields`) instead of the sideways-scrolling rail, so every stepper is fully visible with 44px targets and 8px gaps at 390 and 320. (3) `.fx-notice__act` (the inline Sign in link in the signup "email already has an account" notice) is a real 44px-high inline-block with cancelling negative block margins, replacing the `::after` outset that left the element measuring 45x20. (4) In-app "Manual target(s)" progression wording and the routine unit copy ("routine/cardio targets") now say "goal" (`progression-playbooks`, `progression-status-display`, `progression-scenarios`, `exercise-info`, `ProgressionPlaybookEditor`, `RoutineEditorForm`, dev fixtures). Event ids (`manual_target_change`), identifiers, stored event reasons and legal copy are unchanged.
- WHY it changed: the integrated QA pass at Chrome 390, WebKit 390 and Chrome 320 flagged all four.
- Rule: A popover must be clamped to the viewport and must not cover content it does not need to; a tap target is a real 44px box, not an invisible outset on a 20px element (measure the element, not the hit area). The word "Target" does not appear in UI copy.
- Failure Mode: A horizontal-scroll rail of three 44px steppers cannot fit 320 wide; the third stepper hides off-screen with no cue. Use the wrap grid for any dock that must show every field.
- Decision: the Delete panel can still touch the right-most chip of a full 7-day strip at 320 because any below-trigger popover is wider than the free space; the compact width keeps it clear for the common 3-4 day strip. Owner may want a sheet instead of a popover for that card.
- Evidence: `ui-foundation.dom` (resolveMenuPlacement, compact menu), `SessionRowCards.contract` (dock wrap plumbing), `AuthShell.contract` (44px notice action), `progression-status-display.test` (goal wording); phone-sized captures at Chrome 390 / 320 and WebKit 390.
- Status: Source only; not deployed. Nothing checked on a real phone.
