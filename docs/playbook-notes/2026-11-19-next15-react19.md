## 2026-11-19 - FF-PLATFORM-001: Next 15.5 + React 19

- Type: framework upgrade (no product behaviour change intended)
- WHAT changed: next 14.2.35 -> 15.5.29, react / react-dom 18.3.1 -> 19.2.9, eslint-config-next 15.5.29, @types/react(-dom) 19.2 (exact pins). The official codemod `next-async-request-api` awaited params, searchParams, `cookies()` and `headers()` in 49 files; sync helpers keep the codemod's `UnsafeUnwrapped*` cast (supported on 15, removed on 16). Every dev page calls its production guard before awaiting props again (the codemod had put the await first). Next 15 moved the internal redirect/not-found predicates, so they now come only from `src/lib/next-navigation-errors.ts` (with a unit test that throws real `redirect()` / `notFound()`). `experimental.staleTimes.dynamic: 30` keeps the Next 14 client router cache timing. React 19 typing: `JSX` imported from react, `useRef` given an initial value. No route, persisted data, env or flag change.
- WHY it changed: Next 14 is past end of support and the remaining security fixes only ship on newer majors (card FF-PLATFORM-001; plan in `docs/PLATFORM-MIGRATION-READINESS.md`).
- Rule: A guard that must run first (dev-route guard, NODE_ENV check) stays the first statement even after a codemod rewrites the signature; `src/lib/dev-route-guard.test.ts` and `tests/screen-header-contract.test.mjs` enforce it.
- Rule: Never import `next/dist/...` internals from a page or action; add the predicate to `src/lib/next-navigation-errors.ts` so an upgrade breaks one file and its test.
- Failure Mode: The async-request codemod inserts `const searchParams = await props.searchParams;` at the top of the body, above an existing fail-closed guard; an await before the guard lets the page start work before it is withdrawn. A not-found check that compares `digest === "NEXT_NOT_FOUND"` silently returns false on Next 15 (`NEXT_HTTP_ERROR_FALLBACK;404`), so a try/catch would swallow `notFound()`.
- Evidence: typecheck, lint, test:dom, test:all, build, npm run verify (results in the PR body); headless standalone checks of the local build.
- Status: Source only; not deployed. Signed-in flows (sign-in, Today, a session, export, sign-out) cannot run locally (no Supabase env locally) and need an unaliased build check before alias. Next 15 security releases end 2027-01-31, so Next 16 is the next step.
