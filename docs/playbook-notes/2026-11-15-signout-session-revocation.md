## 2026-11-15 - Sign-out revokes the auth session on the server

- Type: Security fix (reliability lane; proposed card FF-RELIABILITY-004; found by the DOD 07.4 production replay on build c48235cb)
- WHAT changed: `DELETE /auth/session-sync` (the sign-out cookie cleanup) now revokes the auth session behind the request's own `sb-access-token` / `sb-refresh-token` cookies before clearing them (new `src/lib/auth/sign-out-revocation.ts`, wired in `src/lib/auth-handoff-handlers.ts`). It calls GoTrue `/logout?scope=local` with the user's own access token (renewed from the user's own refresh token when the access cookie is missing or expired). No service role, no env, no database change. `SignOutButton` now calls the server route first, then `supabase.auth.signOut({ scope: "local" })`. The route response gains `signOut: "revoked" | "already-invalid" | "no-session" | "failed"`; cookies are cleared in every case.
- WHY it changed: Sign-in happens on the server and through the portal handoff, so the browser Supabase client has no persisted session. `supabase.auth.signOut()` then has no access token and auth-js skips `/logout` (`GoTrueClient._signOut`: the call is guarded by `if (accessToken)`). Only the cookies were cleared; the auth session stayed live, so a copy of the pre-sign-out cookie kept working (200 from `/api/history/*`, `/today`, and a session-start write) until the refresh token expired. Server reads already use `supabase.auth.getUser()` with the access token, and auth-js 2.97 documents that a JWT whose `session_id` is not an active session returns session-missing, so a revoked session is rejected by the existing reads without further change.
- Rule: Sign-out is complete only when the auth session is revoked server-side. Clearing cookies and calling a browser-client `signOut()` that has no session do not count.
- Failure Mode: A client-side `signOut()` on a client that never held the session is a silent no-op. A cookie-only mirror therefore needs its own server revocation step.
- Decision: Scope `local` (this session; the portal shares the session id so it is signed out too; other devices stay signed in). `global` is the one-constant change `SIGN_OUT_REVOCATION_SCOPE` if Zac wants "sign out everywhere".
- Evidence: Unit tests `src/lib/auth/sign-out-revocation.test.ts` and `src/app/auth/session-sync/route.test.ts`; contract pin `src/app/account/accountSurface.contract.test.ts`. Production replay (DOD 07.4) is for the Atlas session after deploy.
- Status: Source only until deployed. Server-visible change: sign-out now makes one to two auth-server calls (bounded to 4 s) and the DELETE JSON body has a new `signOut` field.
