## 2026-11-15 - Fitness hands account edits to the portal; auth screens mirror the shared copy matrix

- Type: Product / design-system change (FF-DESIGN-001, Auth Surface v2 follow-up, lane H2)
- WHAT changed: The in-app username/email form (`AccountSettingsForm`) and password form (`AccountPasswordSection`) are deleted. `/account` stays for direct visits as a read-only screen: Username, Email and Password rows show the current value and link to `account.fawxzzy.com/account?app=fitness` (the password row goes to the portal's Reset password). `AccountPortalReturnRefresh` refreshes the server render when the person comes back from a portal link (bfcache restore or tab return), and Settings also syncs the remembered sign-in name. Sign out = this device only: server revoke (#263), local sign-out, then ONE `window.location.assign` (portal `/signout?app=fitness` in a browser tab, `/login` in the installed app), with a `Signing out…` disabled state. A separate `Sign out everywhere` link goes to the portal Account page (its two-step action). The remaining lime auth accent (`160 223 56` / `190 242 100`) is now the standard green. Copy mirrors FawxzzyWeb `copy-matrix.ts`: `signup_failed` shows `page.crash`, `email_required` shows `reset.sendfail` (the Fitness-only `signup.failed` and `reset.unavailable` ids are gone). The crash and global-error screens are `Could not load` + one `page.crash` notice + Try again + `Go to Today`; the 404 is `Page not found` / `That page does not exist.` / `Go to Today`.
- WHY it changed: One place to change identity (the portal) instead of two forms that could drift; the portal has no in-place change-password, so Fitness keeps none. Auth screens must read identically across Fawxzzy apps; "Something went wrong" is retired copy in the shared matrix.
- Rule: A shared constant used by a server component never lives in a `"use client"` module (it arrives as a client reference, not its value); put it in a plain lib module (`ACCOUNT_PORTAL_LINK_ATTRIBUTE` in `src/lib/account-portal.ts`).
- Rule: Fitness auth copy is checked id by id against FawxzzyWeb `src/lib/auth/copy-matrix.ts`; a Fitness-only notice id is a drift, not an addition.
- Failure Mode: A sign-out that calls `router.replace` and then a hard navigation can race; one navigation only. In a browser tab, signing out to `/login` alone bounces through a still-live portal session and signs the person straight back in, so the browser path goes through the portal `/signout`.
- Decision: Account rows return to `/settings` (the portal `returnTo` allowlist for `/account` paths is not verified). `changePasswordAction` / `updateAccountEmailAction` stay in `src/app/settings/actions.ts` (tests still cover them); retiring them is a follow-up.
- Evidence: `src/app/account/accountSurface.contract.test.ts`, `src/lib/account-portal.test.ts`, `src/components/error/errorScreens.contract.test.tsx`, `src/components/auth/authMessages.test.ts`, `src/app/login/accountSurfaceParity.contract.test.ts`; dev auth-screen-lab screenshots at 390x844 and 320x568 (DPR3).
