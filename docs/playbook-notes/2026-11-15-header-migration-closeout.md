## 2026-11-15 - Header migration closeout: the old header pieces are deleted, and a test keeps them out

- Type: UI (FF-DESIGN-001 lane H3; implements DESIGN-CONTRACT section 15)
- WHAT changed: Both Add exercise routes (routine day and live workout) share one detail frame, `AddExerciseScaffold`: title `Add exercise`, subtitle `<day> · <routine>`, Back on the left. Create day and Days have extracted frames (`CreateDayScreen`, `DaysLibraryScreen`) that the route and the new fail-closed `/dev/detail-screens` fixture both render. The dev fixtures (mobile regression, UI contract, UI system, measurement combos) use `ScreenHeader` or plain body headings. Deleted once nothing used them: `AppHeader`, `SharedScreenHeader`, `BackButton`, `TopRightBackButton`, `RoutineDayHeaderTitle`, `standaloneHeaderFamily`, `ExerciseChooserScreenFamily`, `RoutineAddExerciseScaffold`, `RoutineEditorPageHeader`, `header-info-rail`, the legacy `headerTokens` and `fitnessDesignPrimitiveClassNames.headerFamily`, and four unused `header-meta` helpers. Empty states in Routines, the routine overview and Days use a secondary action because the dock already holds the primary. The Create day name field is the C14 `FormField`.
- WHY it changed: Section 15 says every screen, fixtures included, uses the one header. While the old pieces still existed, any new screen could pick them up again.
- Rule: After a migration, delete what it replaced and add a banned-identifier test to CI with a mutation case. A file-exists check alone lets a copied component back in under the old name.
- Pattern: Pull a route's screen frame into its own component so a signed-out `/dev` fixture renders exactly what the route renders. Pin the route test to that frame, not to the page.
- Failure Mode: Matching on whole identifiers matters. `\bBackButton\b` must not catch `ScreenHeaderBackButton`, and comments are stripped first so a note about a deleted name does not fail the check.
- Decision: The frozen truth-pack `header` primitive keeps its id and invariants text. Only `sourceSurfaces` moves to the live files, because the old ones are deleted. Rewriting the invariants for the new header is a truth-pack owner follow-up.
- Evidence: `tests/screen-header-contract.test.mjs` (banned pieces, raw title classes, Add exercise frame, fixture guard). Playwright headless, 390x844 DPR3 and 320x568, touch, standalone, against `/dev/detail-screens`. On all 6 screens: one-line title with ellipsis, Back 44x44 at 12px from the left, no tab bar, no horizontal overflow.
- Status: Source only, headless. Not checked on a real phone.
