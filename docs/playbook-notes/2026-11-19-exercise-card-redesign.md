## 2026-11-19 - Exercise card redesign: goal line, side column, one progress bar, Promote seam, done check

- Type: UI (source; no progression rule, server action or data change)
- WHAT changed: `ExerciseRowCard` (Today, in-session summary, view-day, day editor, workout in progress) lost the AUTO / SESSION / SET bubbles and the `Target` block. The goal is one line from the new `formatExerciseGoalDisplay` (`3 × 8 @ 60 kg`, `18:00 · 2 km`, never `18:00 s`) with a spoken form for screen readers. The thumbnail moved top-right and the info / drag controls bottom-right in one side column. The logged-sets bar and the progression bar are one `ExerciseProgressBar`; at 100% with a wired `progress.promote` seam it shows a Promote button at the right end (hidden otherwise; `TodayDayPicker.onPromoteExercise` is optional and not passed yet). New `PromoteCelebration` modal (old → new stat rows, glow, shine). Completed rows show a check mark beside the name with a short pulse (off under reduced motion) instead of a DONE chip. `0 / 1 sets` reads `0 / 1 set`. New dev fixture `/dev/exercise-cards`. Details: `docs/design-system/CARD-SYSTEM.md` section 7.6.
- WHY it changed: Zac's Today review (2026-11-19): the bubble row was noise, the goal read as a form label, the image and info button competed, and finished rows needed a clearer, quieter cue.
- Rule: An exercise goal is formatted once (`formatExerciseGoalDisplay`); cards never print a raw unit string. A new card action that needs a server call ships as an optional prop seam that renders nothing until wired.
- Decision: Info button bottom-right (image owns top-right, thumb reach, ends the reading order, lines up with the progress row). The Promote button is a seam, not wired to a server action here; the manual promote action is a separate lane. The automatic trigger and the `CardActionRow` Promote / Revert footer are untouched.
- Failure Mode: `formatDurationPreview` still appends ` s`; it is shared with the quick-log button and other screens, so the card formatter strips it locally instead of changing the shared helper (follow-up).
- Evidence: `src/lib/exercise-goal-display.test.ts`, `src/components/workout/PromoteCelebration.test.tsx`, `TodayCards.contract.test.tsx`, `SessionRowCards.contract.test.tsx`, `EditDayCards.contract.test.ts`, `tests/dom/card-interactions.dom.test.tsx` (Promote visibility, one call per tap, pending ignores taps); headless screenshots at 390x844 DPR3 standalone on the dev fixtures.
- Status: Source only, headless-only, not device-checked.
