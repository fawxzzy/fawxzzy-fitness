## 2026-11-25 - Integrated main QA pass (copy and notice visibility)

- Type: UI polish from the post-redesign integrated QA (no data, route, env or flag change)
- WHAT changed: (1) The routine day-move server action error `Target day not found.` now reads `Day not found.` (`src/app/routines/actions.ts`); the common rule for the redesign is that the word "Target" does not appear in UI copy. (2) The auth notice box (`AuthNoticeSlot` in `src/components/auth/AuthShell.tsx`) mounts a new client helper `NoticeScrollIntoView` that scrolls the notice into view with `block: "nearest"`. On a 320x568 phone the auth body is a short scroller and a two-line notice (for example "That email already has an account. Sign in") landed below its fold with no cue.
- WHY it changed: the integrated QA captured every fixture state at Chrome 390, WebKit 390 and Chrome 320 and found these two gaps; everything else it flagged is a product or legal decision left for the owner (see Decision). Also changed: dev gallery caption "no target" -> "no goal".
(3) `AppLoaderHost` un-latches the hidden boot icon when a wait arrives after the cover began to leave (`src/components/AppLoaderHost.tsx`): the loading fixtures showed a blank green cover with no icon (inline `animation: none; opacity: 0` on the stage, cover visible) until the wait ended.
- Rule: Notices are shown in the in-flow notice box only; a freshly shown notice must be visible without the user hunting for it. `AuthShell.contract.test.ts` pins the helper; `app-loader.contract.test.ts` pins the icon un-latch.
- Failure Mode: A fixed-height scroller (`.fx-body`, overflow auto) hides a notice that appears below the fold on short phones; role=alert announces it to screen readers but sighted users see nothing. Check 320x568 for every new in-flow notice.
- Decision (not changed here, owner to decide): "target" still appears in the Privacy and Terms legal copy, in the progression library vocabulary ("Manual target(s)" in `src/lib/progression-*.ts`, `ProgressionPlaybookEditor`, `RoutineEditorForm` unit copy) and in dev fixtures. Pre-auth, install and error screens use the auth shell (large white title, solid green pill CTAs) while in-app screens use the dock buttons; in a plain browser (not installed) `/login` renders the account-portal style (lime accent). These are inconsistent across lanes but intentional per earlier decisions.
- Evidence: PR body lists typecheck, lint, test:all, test:dom, build, `npm run verify`, each generator `--check`, and the phone-sized captures.
- Status: Source only; not deployed.
