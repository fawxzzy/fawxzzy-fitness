## 2026-11-19 - Sign-out revocation verified live; #282 reviewer P2s

- Type: UI polish + auth regression test + truth pack (no behaviour change to sign-out)
- WHAT changed: (1) The Export name and Discord verification token fields are named by their full visible label again ("Export name", "Discord verification token"; #282 had shortened them to "Name" / "Verification token"). `SettingsCards.contract.test.tsx` now asserts that each label's `for` matches the `id` of an input in the same markup. (2) The three Exercise-notes / Day-notes textareas in `LogAuditClient` no longer carry `h-auto` next to the `h-11` of `formFieldControlClassName` (`cn()` does no Tailwind dedupe, so the winner was stylesheet order). The suggested `!h-auto` was measured and rejected: it beats the inline height that `autoSizeTextarea` sets and froze a 4-line note at 44px (44 vs 116 px); without `h-auto` the inline height wins, 44px at rest and 116px for 4 lines. A FormField contract test now fails on an `h-*` next to the control class. (3) `primitives.v1.json` drops the stale `eyebrow` ref from the header `shared` variant (ScreenHeader has no eyebrow). (4) `auth-session.test.ts` pins that the auth server's answer for a revoked session (403 `session_not_found`) is classified as a session-expired login.
- WHY it changed: #282 review P2s; and FF-ACCOUNT-005 ("revoke the server session on sign out"). The revoke already shipped in #263 (`DELETE /auth/session-sync` revokes the session behind the cookies with the user's own tokens, scope local) and is live in build 02917bfb. A live replay on 2026-11-19 (QA account claude1, headless installed-app emulation) showed: DELETE answers `{"ok":true,"signOut":"revoked"}`; a copy of the pre-sign-out cookies then gets HTTP 200 from `/today` and `/settings` whose streamed body carries `NEXT_REDIRECT` to the session-recovery route and none of the account data, while the same copy before sign-out renders the screen. The 200 status is Next streaming behind `loading.tsx` (a redirect after the first flush cannot change the status), so "still serves 200" on its own is not proof the session is live.
- Rule: Judge a replayed cookie by the body (redirect signal, no account data), not the HTTP status of a streamed page.
- Failure Mode: Reading `GET /today` = 200 as "the old session still works" sends a fix at a revoke that already works.
- Decision: No server change for FF-ACCOUNT-005. An unexpired access token is rejected because every signed-in page calls `getUser()` against the auth server (session lookup), not because the JWT expired. No database, env, credential or migration change.
- Evidence: unit tests (auth-session, sign-out-revocation, device-sign-out, SettingsCards, FormField, design-system contract); live replay as described above (headless only, not a real phone).
- Status: Source + headless live replay; not checked on a real phone.
